## Lectern「本地可信交付」P0 落地

在 zmzai-lectern 实现 local trusted delivery P0，形成「一轮 Agent 工作 → 可审查/可验证/可安全合并」的闭环（不含浏览器 QA/截图/服务启动器/完整 VS Code terminal）。

### 新增文件（lib/ 逻辑层 + app/ API 层 + 组件 + 测试）
- `lib/delivery-types.ts` — 核心类型：`TaskDelivery`/`DeliveryAttempt`（不可变）/`DeliverySnapshot`/`CommandRun`/`VerificationAggregate`/`DeliveryMergeResult`/`DeliveryMergeRejectReason` 等
- `lib/delivery-state.ts` — 状态机纯函数（无 IO）：`TRANSITIONS` 表 + `canTransition`/`assertTransition`/`aggregateVerification`/`resolveVerificationStatus`/`canAccept`/`isSnapshotStale`/`TERMINAL_STATUSES`
- `lib/delivery-git.ts` — Git 原语（execFile，杜绝 shell 注入）：`git`/`headSha`/`currentBranch`/`toBranchRef`/`worktreeFingerprint`/`materializeDeliveryCommit`（临时 index 物化 immutable commit/tree，不碰 worktree）/`casUpdateRef`（update-ref 原子 CAS）/`listChangedPaths`（服务端推导变更清单）
- `lib/delivery-path.ts` — `resolveCwdWithin` 路径守卫（纯函数，独立成模块以避开 node:sqlite 转译），拒绝绝对路径/`..`/跨 root
- `lib/sanitize.ts` — 脱敏（KEY=VALUE/Bearer/云密钥前缀/连接串口令）+ UTF-8 安全截断（`buf[end]` 后退到字符边界）+ 容量上限（命令输出 2MiB / 文本 8MiB）
- `lib/evidence-packet.ts` — 最小证据包：`commandTail`/`failureSummary`/`buildEvidencePacket`/`isDuplicateEvidence`（去重）
- `lib/delivery.ts` — P0 核心：SQLite 持久化（`deliveries`/`delivery_attempts`/`command_runs`）+ `resolveOwner`（从 sessionId 推导 owner，绝不信任客户端 owner/root/path）+ `beginAttempt`/`transitionToVerifying`/`finishVerification`/`recordCommandRun`/`mergeAttemptCas` 等
- `app/api/deliveries/route.ts` — `GET /api/deliveries?sessionId=`
- `app/api/deliveries/attempt/route.ts` — `POST /api/deliveries/attempt`（begin/verify/commands/finish/check/accept/discard/cancel），owner 全从 sessionId 推导，required 伪造降级 advisory，cwd 服务端 resolve
- `components/DeliveryReview.tsx` — 最小证据展示（变更文件/验证状态/命令记录/不可合并原因/接受/丢弃/验证）
- 测试：`delivery-state.test.ts`(14)/`delivery-path.test.ts`(6)/`sanitize.test.ts`(11)/`evidence-packet.test.ts`(7)/`delivery-git.test.ts`(7)

### 关键实现要点
- 状态机：running/verifying/ready_for_review/verification_failed/unverified/cancelled/accepted/discarded；required 全过→ready_for_review，任一 required 失败→verification_failed，零 required→unverified
- 验证快照：进 verifying 时用 `GIT_INDEX_FILE=<tmp>` + read-tree/add -A/write-tree/commit-tree 物化 immutable delivery commit，不改写用户 worktree
- 合并 CAS：`git update-ref <refs/heads/branch> <mergeCommit> <verifiedBaseHeadSha>`，precondition 失败即拒绝；`snapshot_stale` 永不可接受
- **changedPaths 改为服务端 `listChangedPaths` 推导**（本次收尾：`transitionToVerifying` 去掉客户端参数，符合「不信任客户端路径」原则）

## 打 mac + win 安装包（v0.4.0）

- 产物（dist/）：`Lectern-0.4.0-arm64.dmg`(330M)、`Lectern-0.4.0-arm64-mac.zip`(358M)、`Lectern-Setup-0.4.0.exe`(278M, NSIS)、`Lectern-0.4.0-win.zip`(372M)。
- **坑 1 — pnpm 不在 PATH**：本机 shell 找不到 `pnpm`（nvm v26.2.0 才有真 pnpm，v24 是 corepack 链接）。构建脚本内 `pnpm` 直接裸调用会 command not found。绕法：`export PATH="/Users/ulanxx/.nvm/versions/node/v26.2.0/bin:$PATH"` 前缀。
- **坑 2 — npm install 卡死**：环境里有 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:57468`（WorkBuddy 沙箱代理），npm install 走它访问 registry.npmjs.org 会卡 30+ 分钟无进度。绕法：构建命令前剥代理 `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy`，npm ping PONG 正常，install 44s 完成。**教训：本机所有 npm/pnpm 联网命令都要剥代理**。
- **坑 3 — 两脚本互斥清 dist**：`build-mac.sh` 与 `build-win-cross.sh` 都会 `guard_mv dist`，后跑的清掉先跑的产物。要一次打两个平台，需先备份先跑的产物到 /tmp，最后合并回 dist。

## 修复「QA 结束悄无声息，无总结陈词和产物卡片」（09-03 早）

**根因（代码级，已逐行核实）**：
- 「任务小结」其实是**半成品**——framework 源码 `summarizeRun`（runner.ts:835）确实存在且被 runLoop finally 调用，但 `session.summary` 事件在 4 处静默 return（summaryModel 缺失/无可总结消息/生成失败/超时/空文本），任一出问题就不发事件 → lectern 投影器 `summary=null` → `SummaryCard`（ChatView.tsx 已接但依赖 summary 非空）不渲染。
- `lib/runtime.ts:267` summary 模型硬编码 `gpt-4o`（`OPENAI_MODEL ?? "gpt-4o"`），实际走 relay，模型名大概率对不上 → `provider.getModel("gpt-4o")` 拿不到有效 ref → 稳定命中「summaryModel 缺失」路径 → 稳定不发 summary。
- 产物卡片：`artifact.created`（runner.ts:172 有发射）在 `chat-projector.ts` **零消费**，`ChatViewData` 无 artifacts 字段。

**修复（两仓两个 commit）**：
- framework `981a9c34`：`summarizeRun` 兜底必发 `session.summary`（三态模板文案 + meta 统计），AI 成功用真实文本、失败回落模板。加了 changeset `summary-fallback-always-emit.md`（patch）。
- lectern `4c7e432`：投影器消费 `artifact.created`，**按 `session.summary` 作 run 边界切分产物**（本轮累积 → summary 到达时封存为 summaryArtifacts 并清空累积器）→ 多轮会话每轮总结卡只挂自己的产物、不跨轮累积。新增 `Artifact` 类型 + `ArtifactCard` 组件（挂在 SummaryCard 下方）+ 6 项单测。

**关键认知（复用价值）**：
- framework 里 `artifact.created` 事件 **不带 runId/taskId**，要「按本轮任务」归集只能靠投影器用 `session.summary` 事件做 run 边界切分（每个 summary 封存一批）。
- `SummaryCard` 组件**本来就在 ChatView.tsx 里且已接线**（之前误判为「完全没接」是因为 Grep 工具对 `<SummaryCard` 换行写法匹配失败）。真正没接的是 artifact 产物。
- **Grep 工具（ripgrep）在 zmzai 仓库有随机返回空的问题**——搜不到不代表没有，务必用 Bash `grep -n` 或 Read 二次确认，否则会误判「代码不存在」。
