# Lectern 对话优先视觉改版设计规格

**日期：** 2026-09-17  
**状态：** 待实施
**方向：** A — 安静宽松、对话优先

## 0. 给实施模型的任务

按照本规格重构 Lectern 的桌面、平板和移动端工作区界面。会话必须成为稳定的视觉主区域；侧栏负责导航，右侧工作台按需打开。重点解决右侧工作台拖动后会话被截断、长用户消息破坏布局、界面圆角和密度缺乏统一、状态与操作重复的问题。

这是一个独立的前端界面任务。它不负责修改 Agent 的持续执行、自动续跑或可信完成判定；这些行为由 [`2026-09-17-lectern-continuous-task-execution-spec.md`](./2026-09-17-lectern-continuous-task-execution-spec.md) 定义。实施本规格时应保留现有任务行为，只调整布局、视觉层级、响应式交互和前端布局状态。

实施完成后必须提供桌面和移动端截图、自动化回归结果及逐条验收说明。不能只修改颜色、圆角或几处 CSS 后宣称完成。

## 1. 背景与决策

Lectern 当前同时展示项目导航、会话、任务状态、已读文件、输入配置和右侧工作台。各区域使用了不同的圆角、密度和表面样式，运行状态也在多个位置重复出现。右侧工作台展开时会持续争夺宽度，使会话阅读区失去稳定的视觉中心。

本次选择“安静宽松、对话优先”：会话是默认主舞台，工作台作为按需展开的成果与审查空间。界面保留现有能力，通过收敛层级、组件外观和展开规则，使用户在任务运行、等待输入和查看成果时都能明确知道当前重点。

本规格补充并覆盖 `2026-09-02-lectern-visual-system-realignment-spec.md` 中与“紧凑工程工作台”、3–4px 控件圆角和工作台常驻有关的要求。其他既有功能规格继续有效。

## 2. 目标

- 让会话在新建、空闲和运行阶段保持唯一的视觉主轴。
- 右侧工作台只在用户主动打开后占用布局宽度，并且拖动时不截断会话内容。
- 用统一的圆角、边框、间距和字号规则减少拼装感。
- 将任务状态、项目上下文和运行配置放到用户能理解的位置，消除重复信息。
- 保留文件、审查、成果预览、终端、模型和权限配置等现有能力。
- 在窄窗口中优先保护会话可读宽度，避免三个区域互相挤压。

## 3. 非目标

- 不更换品牌色或重新设计品牌标识。
- 不修改任务、消息或成果的后端数据结构。
- 不移除工作台、终端、文件或审查功能。
- 不重做工作台中被预览网页本身的视觉设计。
- 不在本次改版中引入新的协作、版本管理或自动发布能力。
- 不修改 `session.summary`、todo、任务完成判定或自动 continuation 语义。
- 不把后端任务状态重构作为本界面任务的前置条件；现有状态先通过展示适配层呈现。

## 3.1 与持续任务执行规格的边界

两个任务可以分别实施，也可以由同一个模型按顺序实施：

| 范围 | 本规格 | 持续任务执行规格 |
|---|---|---|
| 三栏布局、拖动、断点 | 负责 | 不负责 |
| 消息宽度、Composer、圆角、间距 | 负责 | 不负责 |
| 工作台默认收起与按任务记忆 | 负责 | 不负责 |
| 进度信息的视觉容器 | 负责基础容器 | 提供真实任务数据 |
| 自动续跑、Completion Gate | 不负责 | 负责 |
| “继续下一步”的业务移除 | 暂不改变语义 | 负责彻底移除 |
| “任务完成”的真实判定 | 展示传入状态 | 负责状态来源 |

若先实施本规格，界面必须通过单一 presentation adapter 读取现有状态，避免把旧状态判断散落到新组件中。后续实施持续任务执行规格时，只替换 adapter 的数据来源，不重做布局。

## 4. 页面信息架构

### 4.1 三个区域

1. **侧栏**负责项目与任务切换。它应保持安静、紧凑，并让当前任务和异常状态易于识别。
2. **会话区**负责理解任务、查看过程、响应请求和继续下达指令。它始终是默认主区域。
3. **工作台**承载文件、审查和成果预览。默认收起，由用户按需打开。

终端继续由会话区底部的 Debug Area 承载，不移动到右侧工作台。Debug Area 与工作台是两个独立面板，各自保留现有状态和尺寸控制。

### 4.2 默认布局

- 新任务、空闲任务和运行中的任务默认只显示侧栏与会话区。
- 工作台收起时保留一个清晰的“打开成果/工作台”入口，不预留空白栏位。
- 生成成果时不自动展开工作台。会话区显示一次“成果已生成”的上下文入口，用户可从该入口打开对应标签。
- 用户主动打开工作台后，在当前任务内记住其开合、选中的标签和宽度。
- 系统状态变化不能覆盖用户对当前任务的显式开合选择。`review_ready` 可以突出打开入口，但不能强制展开。
- 切换任务时恢复目标任务自己的工作台状态；没有已保存状态时使用默认收起。

## 5. 核心区域设计

### 5.1 顶部任务上下文条

顶部只保留一条稳定的任务上下文：

- 主信息：任务标题。
- 次信息：项目、工作树/分支和当前步骤，空间不足时按此顺序保留。
- 状态：运行、等待授权、失败、待审查、已交付等只在这里显示一个主状态；消息流中的状态只作为事件记录，不复制常驻徽标。
- 操作：停止、重试、打开成果等与当前状态直接相关的操作保持可见；低频操作进入溢出菜单。
- 模型、推理强度和权限归入“运行配置”，不依赖悬停才能发现。

标题可截断，但项目和工作树需要有可见的短标签。Tooltip 只补充完整文本，不能承载唯一的关键信息。

### 5.2 会话流

- 消息列与 Composer 使用同一宽度和左右基线，形成稳定的单一阅读轴。
- 助手消息采用开放式排版，不包裹在整块卡片中。
- 用户消息可使用浅色气泡，最大圆角 12px；长消息允许自然换行并受消息列最大宽度约束。
- “已读文件”默认折叠为一行摘要，例如“已读 8 个文件”，展开后再显示文件列表，避免顶部形成长串标签墙。
- 工具过程和思考过程使用轻量折叠行。进行中的步骤可以显示细窄状态标记，但不再额外创建大卡片。
- 搜索入口并入任务上下文条或会话内快捷操作，移除只为搜索存在的一整行固定栏。
- 等待授权、运行失败和需要用户输入时，在相关消息附近显示明确的操作区，同时同步顶部唯一主状态。

### 5.3 Composer

- Composer 与消息列等宽，使用 12px 圆角和清晰但克制的边框。
- 文本输入是主要区域；发送/停止是唯一高强调按钮。
- 附件保留独立入口。
- 模型、推理强度、权限和技能统一进入“运行配置”，在 Composer 底部用一个可读摘要入口呈现。
- 上下文推荐操作可以将建议填入草稿，但不得自动发送。
- 多行内容增长到合理上限后在输入框内部滚动，不能推走顶部任务上下文或导致页面横向溢出。

### 5.4 侧栏

- 当前任务用低对比底色和一条明确的选中标记表达，不叠加多层边框。
- 任务标题、状态和时间保持固定对齐。常用状态用文字加小标记，不只依赖颜色。
- 运行中、等待授权和失败的任务可显示与状态直接相关的操作；其他操作放入行尾溢出菜单。
- 项目区、任务区和账户区使用分隔线划分结构，避免每一区都做成独立卡片。
- 收起侧栏后保留项目/任务入口和未处理状态提示。

### 5.5 右侧工作台

- 工作台沿用“审查 / 文件 / 成果预览”等现有标签，标签栏与页面视觉令牌一致。
- 打开时使用清晰的一条分隔线与会话区区分，不增加浮层阴影或大圆角容器。
- 拖动分隔条只改变两侧宽度；会话区和工作台都设置正确的 `min-width: 0` 与溢出边界，内容在各自区域内换行或滚动。
- 当窗口无法同时满足会话最小可读宽度与工作台最小宽度时，工作台改为覆盖式抽屉。关闭抽屉后恢复完整会话区。
- 预览失败、成果不存在或加载超时时，在工作台内显示原因、重试和返回入口，不主动改变面板开合状态。

#### 5.5.1 分栏布局实现约束

桌面并排布局必须使用明确的可收缩链路。推荐结构：

```css
.app-shell {
  display: grid;
  grid-template-columns: var(--sidebar-width) minmax(0, 1fr);
  min-width: 0;
}

.task-main {
  display: flex;
  min-width: 0;
  overflow: hidden;
}

.conversation-pane {
  flex: 1 1 auto;
  min-width: 0;
  overflow: hidden;
}

.workbench-pane {
  flex: 0 0 var(--workbench-width);
  min-width: var(--workbench-min-width);
  max-width: var(--workbench-max-width);
  overflow: hidden;
}
```

要求：

- 从页面根节点到消息正文之间，所有参与横向 flex/grid 的祖先都要检查 `min-width: 0`。
- 消息列、Markdown、pre、table、图片、iframe 和文件标签不能撑大父容器。
- 正文自然换行；代码块、表格和超宽资源在自己的容器内横向滚动。
- 不得用页面级 `overflow-x: hidden` 掩盖真实溢出问题。
- 拖动期间只更新宽度变量，不改变消息 DOM、滚动锚点或工作台内容。

#### 5.5.2 拖动算法

桌面工作台宽度使用以下边界：

```ts
const conversationMin = 480;
const workbenchMin = 360;
const workbenchMax = Math.min(760, availableWidth * 0.58);
const nextWidth = clamp(pointerRightDistance, workbenchMin, workbenchMax);
```

如果 `availableWidth < conversationMin + workbenchMin + dividerWidth`，禁止继续并排压缩，立即切换到覆盖式工作台。拖动分隔条必须：

- 支持 Pointer Events，并在拖动期间 capture pointer；
- 支持键盘左右方向键，每次调整 16px，按 Shift 时调整 48px；
- 暴露 `role="separator"`、方向、当前值、最小值和最大值；
- 双击恢复推荐宽度；
- 到达边界后保持稳定，不发生回弹或指针漂移；
- 不因 iframe 捕获鼠标而中断拖动，必要时在拖动期间启用透明捕获层。

### 5.6 底部 Debug Area

- 终端继续位于会话区底部，不并入右侧工作台，也不进入移动端的成果视图。
- 本次只让 Debug Area 的分隔线、标签、字号、按钮和焦点样式服从统一视觉令牌，不改变 PTY、会话标签或现有收起逻辑。
- Debug Area 展开时缩短会话的可见高度，但不能改变会话列宽，也不能导致页面级滚动；终端内容在自身区域内滚动。
- 窄屏下 Debug Area 仍在会话视图内按需展开。它与侧栏、工作台抽屉互不替代。

## 6. 视觉系统

### 6.1 圆角

| 用途 | 圆角 |
|---|---:|
| 页面结构区、侧栏、工作台、分隔区域 | 0 |
| 小按钮、图标按钮、紧凑控件 | 6px |
| 列表行、菜单、Popover、轻量提示 | 8px |
| Composer、用户消息气泡 | 12px |
| 状态胶囊 | 全圆角，仅限短状态文本 |

禁止在同一层级混用 3px、10px、16px 等未定义圆角。圆角用于表达组件类型，不用于给所有区域增加装饰。

### 6.2 表面与边框

- 页面使用一个主背景、一个轻微抬升表面和一个选中/悬停表面。
- 结构主要依靠间距和单像素分隔线；避免卡片套卡片和多重阴影。
- 阴影只用于需要覆盖其他内容的菜单、Popover 和抽屉。
- 主状态色保持低面积使用，不能把整个大区域染成状态色。

### 6.3 字号与密度

- 会话正文：14–15px，行高 1.6 左右。
- 标题：按层级使用 16–20px，避免同屏出现过多字号。
- 元数据和辅助文本：至少 12px。
- 10–11px 仅用于非关键计数或极短标签，且不能作为唯一操作说明。
- 桌面图标按钮最小点击区域 28px；发送、停止、授权等关键操作最小 32px，并保留清晰的键盘焦点样式。
- 常规间距以 4px 为基准，主要使用 8、12、16、24px。

## 7. 响应式与尺寸规则

- **宽度 ≥ 1180px：** 侧栏常驻并恢复用户上次保存的桌面开合状态；用户打开工作台后可与会话并排。会话区建议最小可读宽度 480px，工作台遵守自身最小宽度。
- **宽度 768–1179px：** 侧栏和工作台都是覆盖层，默认关闭；用户打开其中一个时关闭另一个，选择任务后自动关闭侧栏。进入此区间不改写桌面开合状态。
- **宽度 < 768px：** 会话、侧栏和工作台分别占据单一视图，通过显式返回操作切换；同一时刻只显示一个视图。
- 从窄窗口恢复到 ≥1180px 时，侧栏恢复进入窄窗口前保存的桌面状态；工作台恢复当前任务的保存状态和宽度。
- 所有断点下禁止页面级横向滚动；代码块、表格和终端在自身容器内滚动。
- 分隔条需支持指针拖动和键盘调整。到达最小/最大宽度时给出稳定边界，不产生跳动或截断。

### 7.1 布局状态模型

前端应把持久桌面偏好和当前断点下的临时呈现分开：

```ts
type TaskLayoutPreference = {
  sidebarOpenDesktop: boolean;
  workbenchOpenDesktop: boolean;
  workbenchWidth: number;
  workbenchTab: "review" | "files" | "preview";
};

type ResponsivePresentation = {
  mode: "desktop" | "overlay" | "single";
  activeOverlay: "sidebar" | "workbench" | null;
  activeMobileView: "conversation" | "sidebar" | "workbench";
};
```

约束：

- 进入窄断点只能改变 `ResponsivePresentation`，不能覆盖桌面偏好。
- 工作台状态按任务保存；侧栏桌面偏好可以全局保存。
- 旧版全局工作台宽度仅在目标任务没有偏好时迁移一次。
- localStorage 解析失败、值越界或版本不匹配时回到安全默认值。
- SSR/首屏渲染不能因为读取浏览器存储造成 hydration 报错或明显跳动。

### 7.2 消息和输入区宽度

- 会话内容列使用统一的 `--conversation-content-max`，建议 760–840px。
- 助手消息、用户消息、状态行、附件和 Composer 共享左右基线。
- 用户消息最大宽度建议为内容列的 78%，但在窄屏下可占满可用宽度。
- 任何消息都必须满足 `max-width: 100%`、`overflow-wrap: anywhere`；连续 URL、文件路径和无空格文本不能撑破布局。
- Composer 使用 sticky/flex 布局时必须保留消息区的独立纵向滚动和底部安全间距。

## 8. 状态行为

| 任务状态 | 会话主表现 | 工作台行为 |
|---|---|---|
| 新建 / 空闲 | 聚焦 Composer 和最近上下文 | 默认收起 |
| 运行中 | 顶部显示当前步骤，消息流显示最近过程 | 保持用户选择，不自动打开 |
| 等待授权 | 相关消息处显示授权操作，顶部显示等待状态 | 保持用户选择 |
| 失败 | 相关消息处显示错误摘要与重试 | 保持用户选择，预览错误在面板内处理 |
| 待审查 | 顶部显示“待审查”及打开入口 | 可强调入口，不强制打开 |
| 已交付 | 会话显示交付摘要与成果入口 | 用户点击后打开对应成果标签 |

后台任务在侧栏持续显示状态；当前会话不因其他任务产生事件而自动切换或打开工作台。

## 9. 状态持久化与兼容

- 继续使用现有前端布局状态持久化机制；不增加后端字段。
- 工作台开合、宽度和选中标签按任务保存。读取旧版全局状态时可以迁移为当前任务初值，随后按任务独立更新。
- 自动建议只能改变入口的强调程度，不能覆盖用户已保存的面板选择。
- 保留现有任务、消息、文件、审查、预览、终端、模型和权限流程。

持久化 key 需要版本号。推荐：

```ts
type StoredTaskLayoutV1 = {
  version: 1;
  byTaskId: Record<string, TaskLayoutPreference>;
};
```

写入应去抖；任务不存在或记录过多时清理最旧条目，避免长期使用后无限增长。

## 10. 预计实现范围

主要影响以下现有前端文件，最终计划可根据代码职责微调：

- `app/page.tsx`：页面区域、工作台默认行为、断点和布局状态。
- `app/globals.css`：统一视觉令牌、排版、焦点和响应式样式。
- `components/TaskContextStrip.tsx`：唯一任务状态与可见上下文。
- `components/ChatView.tsx`：消息阅读轴、过程折叠和文件摘要。
- `components/Composer.tsx`：输入层级和运行配置入口。
- `components/SessionList.tsx`：侧栏任务行与状态操作。
- `components/WorkbenchPanel.tsx`：工作台标签、错误态和覆盖式抽屉。
- `components/TaskBarActions.tsx`：状态相关操作的收敛。
- `components/DebugArea.tsx`、`components/TerminalPane.tsx`：只对齐视觉令牌和溢出边界，不改变终端归属与 PTY 行为。
- 新增或整理 `lib/task-layout.ts`：断点模式、宽度 clamp、持久化解析和按任务偏好归一化。
- 新增 `e2e/conversation-first-ui.mjs`：关键断点、浅深主题和长内容截图。
- 更新 `e2e/workbench-resize-ui.mjs`：拖动、键盘、iframe、任务切换和溢出断言。

## 10.1 推荐实施顺序

### 阶段 A：布局基础

1. 抽出 task layout 状态和纯函数测试。
2. 修复 app shell、task main、conversation 和 workbench 的 `min-width`/overflow 链路。
3. 实现桌面并排、平板覆盖和移动单视图三种模式。
4. 实现工作台拖动、键盘调整和边界切换。

### 阶段 B：信息层级

1. 收敛顶部任务上下文条和重复状态。
2. 建立统一消息列与 Composer 基线。
3. 折叠已读文件和工具过程。
4. 收敛 Composer 配置入口与侧栏任务行。

### 阶段 C：视觉令牌

1. 建立圆角、表面、边框、间距、字号和焦点令牌。
2. 逐组件替换散落数值，移除卡片套卡片。
3. 对齐工作台、Debug Area、Popover 和错误态。
4. 检查浅色、深色及 Windows/macOS 字体渲染差异。

### 阶段 D：回归与视觉验收

1. 运行类型检查、单元测试和生产构建。
2. 一次性采集全部关键尺寸与主题截图。
3. 集中修复截图暴露的问题。
4. 最多再做一轮确认截图，避免无止境微调。

## 11. 验证方案

### 11.1 视觉场景

在浅色与深色主题验证以下状态：新建、运行中、等待授权、失败、待审查、已交付和空会话。至少覆盖 1600×900、1440×900、1180px 临界宽度、960px 和 390px。

### 11.2 交互验证

- 打开、关闭、拖动和键盘调整工作台，确认会话内容不会被截断或产生页面横向滚动。
- 生成成果和状态变化时确认工作台不会自动抢占布局。
- 切换两个任务，确认各自的工作台开合、宽度和标签正确恢复。
- 验证侧栏收起、侧栏与工作台覆盖层互斥、断点往返恢复、长标题、长用户消息、代码块和大量已读文件。
- 展开底部 Debug Area，确认它只改变会话可见高度，终端内容在自身区域滚动且不影响会话列宽。
- 仅用键盘完成任务切换、打开成果、调整分隔条、编辑 Composer 和发送/停止。
- 核心操作不依赖 hover；焦点顺序与焦点样式清晰。

### 11.3 回归验证

- 保留现有类型检查、构建和功能测试。
- 增加覆盖对话优先布局的端到端测试，重点断言默认收起、用户选择持久化、1180px 模式切换和无横向溢出。
- 为关键尺寸保留截图产物，用于人工比较层级、密度和视觉一致性。

### 11.4 自动化断言

除截图外，E2E 至少断言：

- `document.documentElement.scrollWidth <= window.innerWidth`；
- 会话 pane 的实际宽度不小于当前模式规定的最小值；
- 长用户消息右边界不超过会话 pane；
- 工作台拖到极值后宽度被 clamp；
- 1179px 下工作台覆盖会话，1180px 下按偏好并排；
- 窄屏打开工作台不会修改保存的桌面 open/width；
- 两个 task 的工作台宽度、开合和 tab 相互独立；
- 展开 Debug Area 不改变 conversation pane 的横向尺寸；
- 键盘能够聚焦和操作分隔条、工作台入口、Composer 和主要按钮。

## 12. 验收标准

1. 新建、空闲和运行任务首次进入时，工作台默认收起，会话是页面最宽且最清晰的区域。
2. 成果生成、进入待审查或任务交付不会自动展开工作台；用户能通过明显入口打开正确标签。
3. 用户主动设置的工作台开合、宽度和标签在当前任务内保持，切换任务后分别恢复。
4. 低于 1180px 时工作台以覆盖式抽屉出现，不缩窄或截断会话内容。
5. 页面只使用本规格定义的结构圆角、控件圆角和气泡圆角；大区不再卡片化。
6. 任务主状态只在顶部上下文条常驻显示；消息流保留事件，侧栏保留任务级状态提示。
7. 模型、推理强度、权限和技能通过一个可发现的“运行配置”入口访问。
8. 已读文件默认显示折叠摘要，不再形成横向标签长串。
9. 所有关键辅助文字不小于 12px，关键操作点击区域不小于 32px。
10. 在规定的桌面和移动尺寸下没有页面级横向滚动，现有核心任务流程通过回归验证。
11. 终端继续由会话区底部 Debug Area 承载；右侧工作台只包含审查、文件和成果预览。
12. 768–1179px 下侧栏与工作台作为互斥覆盖层运行，返回 ≥1180px 后恢复已保存的桌面状态。
13. 右侧工作台在桌面拖到任意合法宽度时，长用户消息、助手正文、代码块和 Composer 都不会被裁切或撑出页面。
14. 拖动分隔条支持指针、键盘和双击复位，包含正确的无障碍语义。
15. 布局偏好按任务隔离，断点切换不会污染桌面偏好，损坏的旧存储值可以安全恢复。
16. 浅色和深色主题在 1600、1440、1180、1179、960、768、767 和 390px 下完成截图验收。
17. 所有布局、视觉和 E2E 测试通过，生产构建无新增警告。

## 13. 明确禁止的实现

- 不得用页面级 `overflow-x: hidden` 隐藏截断问题。
- 不得把会话区设为不可收缩的固定宽度。
- 不得在成果生成、任务运行或窗口变宽时强制打开工作台。
- 不得让平板/移动端的临时开合覆盖桌面持久偏好。
- 不得把所有区域改成带大圆角和阴影的卡片。
- 不得依赖 hover 暴露关键操作或完整状态。
- 不得用大量 10–11px 文字压缩界面。
- 不得把终端移动到右侧工作台。
- 不得重写消息、权限、文件或任务后端协议。
- 不得在未验证关键断点、长消息和拖动边界的情况下完成任务。

1. 完成后的前端代码、布局状态工具和自动化测试。
2. 关键断点与浅深主题截图。

5. 按第 12 节逐条给出的验收报告。
