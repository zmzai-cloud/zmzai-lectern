# 无签名应用内更新（0.5.1）

## 已确认的方案

- 启动后检查固定 HTTPS 发布源；账户菜单可手动检查。
- 仅用户点击后下载。清单 `latest-desktop.json` 同时包含 macOS arm64 与 Windows x64 的版本化文件路径、长度及 SHA-512。
- 路径必须精确匹配平台安装包名称，不允许重定向、任意 URL、降级或未知架构。流式下载限制长度，完成后校验 SHA-512，安装前再次校验。
- macOS：确认后在 Finder 显示 ZIP。用户结束任务、退出应用、解压并替换原应用。不自动修改系统安全设置。
- Windows：确认提示用户结束任务，然后打开 EXE 安装器并退出。安装到原位置，不删除用户数据。便携版用户应自行解压 ZIP；使用 EXE 会进入安装版流程。
- 下载失败显示错误并允许重新检查、重新下载。当前不支持断点续传，也不跨重启恢复下载状态。

## 信任边界

文件哈希用于完整性检查，不等于开发者签名。更新信任依赖固定 HTTPS 域名和 OSS 发布凭据。macOS 仍可能被 Gatekeeper 拦截，Windows 仍可能触发 SmartScreen。没有证书时不承诺无提示或静默安装。

## 发布步骤与验收

1. 构建并校验两端版本文件，Mac 执行隔离用户目录的包内启动测试。
2. 上传版本化文件全部成功后，才发布稳定清单；跨平台 JSON 清单最后发布。
3. 公网回读清单，确认路径、大小、哈希与本地一致。
4. 0.5.0 不含更新入口，需手动安装 0.5.1 一次。

自动化测试覆盖平台选择、版本比较、非法清单、主动下载、损坏/超长下载拒绝、取消安装与安装前再次校验。Windows 原生安装器执行仍需 Windows 环境验证。
